# dsh-zentao

[English](README.en.md) · **简体中文**

DSH 的禅道面板：从 **禅道** 里读取分配给你的需求、任务与缺陷，选一个工作区、手填分支名，把选中的条目派发给 Agent；干完之后把状态和一句备注写回禅道。

本包是从 [dsh-task-hub](https://github.com/handsomeboy65/dsh-task-hub)（TAPD + 禅道双来源）中把禅道部分拆分出来的独立插件，并在拆分基础上补齐了四条能力：**数据通道可切换（含官方 zentao-cli）**、**「我的地盘」+ 侧边栏角标**、**Bug 分诊矩阵**、**状态回写**。

## 四条能力

### 1. 数据通道：v1 / v2 / auto / zentao-cli

设置里的「数据通道」决定读写的接口来源：

| 通道 | 读 | 写 | 说明 |
| --- | --- | --- | --- |
| `v1` | 产品/项目枚举 | ✗ | 拆分前的行为，最保守 |
| `v2` | `/my/*` 服务端「指派给我」 | ✓ | 禅道 22.5+ 有 `/my/*`，22.0+ 有状态流转端点 |
| `auto` | 先探 v2，失败回落 v1 | ✓（v2 生效时） | 换实例不用改配置 |
| `cli` | `zentao my tasks/bugs/stories` | ✓ | 交给官方 [zentao-cli](https://github.com/easysoft/zentao-cli)，登录、分页、版本门槛都由它负责 |

`cli` 通道填的是命令行本身（默认 `zentao`，也支持 `npx zentao-cli@0.4.4` 这种带参数的形式），插件不再保存禅道密码；站点和账号从 `zentao auth status` 里读，任务链接照样能拼对。

**为什么值得切到 cli**：v1 那套「先枚举产品/项目、再本地按处理人过滤」在容器多的时候请求量线性增长；`my` 是服务端过滤。而且写端点、版本判断（`E2010`）、写后回查这些规则 CLI 已经实现过一遍，插件不用二次演绎。

### 2. 「我的地盘」+ 侧边栏角标

- 通道支持 `/my/*` 时，面板默认直接读「指派给我」，不再需要选产品/项目（v1 会退化为枚举，禅道 <22.5 也会自动回退）。
- 侧边栏「禅道」图标上有一个未完成条目的角标。DSH 的 `sidebar.panellist` 只给图标传 `{ size, active }`，**没有 badge API**，所以角标是这个插件自己画的：注册时通过 `inject: () => ({ hooks: { badge } })` 把内部可观察源交给渲染器，图标组件因此拿到 `useBadge(selector)`，再在字形上绝对定位一个气泡。计数由 `/api/zentao/counts` 单独轮询（只取计数，不拉列表），`connection/reset` 时立刻刷一次。

已知取舍：同一个图标在侧栏收起的「More」菜单里会被复用一次，角标会跟着出现；图标外层带 `aria-hidden`，角标对读屏不可见（`label` 仍是「禅道」）。

### 3. Bug 分诊矩阵

「读取范围 = 产品缺陷」时多出一个「矩阵」视图：**严重程度 × 状态**（P1–P4 / 未填 × 待解决 / 已解决 / 已关闭），每格最多列 4 条、多的显示 `+N`；点条目直接进派发弹窗，补充要求会预填「先复现这个 Bug 并确认根因，再动手修改」。状态或严重程度落在轴外的条目不会消失，归到 `stray` 里。

提测之后真正落到开发头上的是 Bug，而「哪个 P1 还没解决」用看板要读 40 张卡，用矩阵一眼就够。

### 4. 回写：派发即开始

派发成功后（任务处于未开始），面板会自动打开回写弹窗，把这次派发写成一次状态流转：

```
PUT /tasks/31/start   { realStarted: "2026-11-17 10:00:00", comment: "已派发 DSH 会话，工作分支 feature/x" }
```

或者走 CLI：`zentao task start --task-id=31 --real-started=... --comment=...`。

弹窗**先给你看这次要提交的请求/命令原文**，点确认才发。Bug 卡片上则多一个「解决」，选 `resolution`（fixed / notrepro / bydesign / duplicate / external / postponed / willnotfix / tostory）加备注。执行完会重新读一次条目，把「禅道现在到底是什么状态」报给你；回查失败就明说没核实，不会假装成功。

## 一个必须承认的接口限制

禅道 API 2.0 的 239 条路径里**没有独立的「加备注」端点**，`comment` 只挂在状态流转上（`start` / `finish` / `close` / `resolve` / `activate`）。所以「写一句备注回禅道」必然同时是一次状态变更——对派发来说这正好是 `start`，语义上也说得通。详见 [docs/zentao-api-notes.md](docs/zentao-api-notes.md)（端点、方法、必填字段都从 `zentao-api` SDK 的机器可读定义里反查得到，不是猜的）。

## 安装

```sh
dsh plugin --profile web add github:SivanCola/dsh-zentao-hub
```

> **包名与仓库名**：包名是 `dsh-zentao-hub`，仓库名也是 `dsh-zentao-hub`（`dsh-zentao` 这个名字在 npm 上已被他人的无关插件占用，所以刻意避开）。目前**没有发到 npm**，安装请用上面这条 GitHub 命令。

装完重启 `dsh web`，侧边栏会出现「禅道」。桌面端请在应用内的 **设置 → 插件** 里安装。需要 DSH 0.2.1+。用 `cli` 通道还需要 `npm i -g zentao-cli`（建议 0.4.4+）并先 `zentao auth login`。

## 首次配置

点面板右上角「设置」：

| 字段 | 说明 |
| --- | --- |
| 数据通道 | `v1` / `v2` / `自动` / `zentao-cli`，见上表 |
| 禅道地址 | 例如 `https://zentao.example.com`，会自动补 `/api.php/v1` 或 `/v2`（cli 通道可留空） |
| Basic Auth | 网关（Apache/Nginx）另有一层 HTTP 认证时打开 |
| 禅道账号 / 密码 | REST 通道必填；密码只写入 DSH credentials（也可用 `ZENTAO_PASSWORD`） |
| 读取范围 | `产品需求`（研发/用户/业务需求）、`项目任务`、`产品缺陷`（Bug） |
| 优先读取「我的地盘」 | 通道支持时默认开；关掉就回到产品/项目枚举 |
| 产品 / 项目 | 点「读取产品」「读取项目」后勾选，或直接填 ID（cli 通道不需要） |

## 派发流程

1. 面板列出当前范围里「处理人 = 我」的条目，按最近修改排序，可筛选 未完成 / 已完成 / 全部，按容器筛选，按任务号、父需求号或标题搜索。
2. 点某条的「派发 Agent」，选「继续原对话」或「新开对话」。首次派发填目标工作区、**分支名称**（完整分支名，如 `feature/order-export`，用 `git check-ref-format` 校验）、worktree 与基线分支。
3. 插件依次：建/复用 worktree → 建 DSH 工作区与会话 → 把标题、来源链接、完整正文、参考资料与工作环境写进**输入框草稿**（禅道正文里的图片与附件也会下载并挂上）→ 会话标题改为 `<分支名> · <标题>` → 跳转过去。**不会自动发送**。
4. 若是任务且还在「未开始」，紧接着弹出回写弹窗，确认后置为进行中并写明这是哪次派发。

## 数据与失败模式

- 设置：`~/.dsh/zentao/settings.json`；派发记录：`~/.dsh/zentao/state.json`（按 `zentao:<条目 id>` 分）。
- 首次启动会把 `~/.dsh/task-hub/` 里的禅道配置与 `zentao:*` 记录搬过来，TAPD 记录留在原地。
- 回写是不可逆的真实操作：计划与执行分两次调用，计划先展示，确认后才落库；`comment` 上限 500 字。
- `cli` 通道没有二进制下载能力（v2 也没有附件下载端点），所以没另配账号密码时草稿里会明确写「附件未随任务下发」，而不是静默丢附件。
- 老版本 `zentao-cli`（≤0.4.1）的参数解析不同，插件会把 `E2009` 识别成「CLI 版本过旧」并给升级命令，而不是报参数错误。

## 开发

```bash
npm test     # 92 项：纯函数、v1/v2/cli 三条读通道、回写计划与执行、git 流程、宿主路由、客户端渲染与角标
```

改完代码后，已安装的 bundle 需要重启 DSH 才会加载新的 JS 代次。

## 限制

- 回写只做「开始 / 解决 / 关闭」三种流转，不做字段编辑、不写工时（`consumed` 字段已透传，但没有 UI）。
- cli 通道的「我的地盘」按 CLI 版本门槛（22.5+）；低于门槛时会明确报 `E2010`。
- 处理人过滤在 v1 通道下仍是本地的，请求量随容器数增长。
- 附件上限：单图 6MB、总附件 20MB。
- 不代替 Agent 执行计划；派发后由会话里的 Agent 自己规划与实现。
