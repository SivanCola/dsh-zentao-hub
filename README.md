# dsh-zentao

[English](README.en.md) · **简体中文**

DSH 的禅道面板：从 **禅道** 里读取分配给你的需求、任务与缺陷，选一个工作区、手填分支名，把选中的条目派发给 Agent 开始干活。

本包是从 [dsh-task-hub](https://github.com/handsomeboy65/dsh-task-hub)（TAPD + 禅道双来源）中把禅道部分拆分出来的独立插件：只保留禅道，去掉 TAPD 的接口、凭据、项目选择器和来源切换，配置与派发记录目录也独立成 `~/.dsh/zentao/`。

## 拆了什么

| 保留 | 说明 |
| --- | --- |
| `lib/zentao.js` | 禅道 REST 客户端。仍是唯一的接口真相来源，新增 API v2 与缺陷（Bug）范围 |
| `lib/work.js` | 单来源适配层（原 `sources.js` 的禅道分支），统一 uid、错误码与完成态过滤 |
| `lib/index.js` | 宿主半边：`/api/zentao/*` 路由、凭据解析、派发编排 |
| `lib/client.js` | 客户端半边：看板/搜索/筛选、设置弹窗、派发弹窗（已删除 TAPD 分区与来源切换） |
| `lib/dispatch.js`、`checkout.js`、`drafts.js`、`prompt.js`、`store.js` | 与来源无关的派发内核，仅去掉了 TAPD 分支与文案 |

| 移除 | 原因 |
| --- | --- |
| `lib/tapd.js` | TAPD 开放平台客户端（token/Basic、自定义字段、截图下载） |
| 来源切换 / 「全部来源」 | 只有一个来源，看板不再需要合并列与按来源报错 |
| TAPD 项目选择器、`nick`/`owner` 字段 | 禅道按产品/项目/执行选容器，处理人由服务端账号决定 |
| `market-entry/` | 市场条目需要一个已发布的仓库地址，等你把包推上去再补 |

## 与原插件的差异

除了「只剩禅道」，拆分时顺手补了三处：

1. **API v2（可选）**：禅道 21.7.8 起提供 `/api.php/v2`（登录改为 `POST /users/login`，需求按 `stories` / `requirements` / `epics` 分集合）。设置里可选 `v1`（默认）/ `v2` / `自动`；`自动` 会先探一次 v2，失败即回落 v1 并记住结果。**注意**：v2 分支按官方端点参考实现，只用假服务器覆盖过，未在真实实例上验证；如果 v2 读不出数据，切回 `v1` 即可。
2. **缺陷（Bug）范围**：设置里的「读取范围」新增「产品缺陷」，走 `/products/{id}/bugs`，归一化后带上严重程度（P1–P4）、解决方案（fixed/duplicate/…）与 `bug-view-{id}.html` 链接。提测之后真正落到开发头上的是 Bug，原来只能看需求/任务。
3. **设置与历史迁移**：首次读取会把 `~/.dsh/task-hub/` 里的禅道配置与 `zentao:*` 派发记录搬过来（TAPD 记录留在原处），老用户不用重新配一遍、也不会丢掉「哪个需求派过哪个会话」。

附件仍然走 v1 的 `/files/{id}` 与 `file-read-*` 页面：v2 文档里没有二进制下载端点。

## 安装

```sh
dsh plugin --profile web add github:<你的账号>/dsh-zentao
```

装完重启 `dsh web`，侧边栏会出现「禅道」。桌面端请在应用内的 **设置 → 插件** 里安装。

需要 DSH 0.2.1 或更新版本。

## 首次配置

点面板右上角「设置」：

| 字段 | 说明 |
| --- | --- |
| 禅道地址 | 例如 `https://zentao.example.com`，会自动补 `/api.php/v1` 或 `/api.php/v2` |
| Basic Auth | 网关（Apache/Nginx）另有一层 HTTP 认证时打开，填网关账号密码 |
| API 版本 | `v1`（默认，插件一直使用的接口）/ `v2`（需禅道 21.7.8+）/ `自动探测` |
| 禅道账号 / 密码 | 禅道登录账号；密码只写入 DSH credentials（也可用环境变量 `ZENTAO_PASSWORD`） |
| 读取范围 | `产品需求`（研发/用户/业务需求）、`项目任务`（项目下各执行的任务）、`产品缺陷`（Bug） |
| 产品 / 项目 | 点「读取产品」「读取项目」后勾选，或直接填 ID，多个用逗号分隔 |

禅道没有「分配给我」的通用接口（v2 的 `assignedtome` 是各列表的参数），插件会先登录拿 token，再按当前账号在本地过滤；「读取范围 = 产品 + 包含已完成」时也会把历史条目一起拉回来。

## 派发流程

1. 面板列出当前范围里「处理人 = 我」的条目，按最近修改排序，可筛选 未完成 / 已完成 / 全部，按容器筛选，按任务号、父需求号或标题搜索。
2. 点某条的「派发 Agent」。
3. 关联过会话的任务可选「继续原对话」或「新开对话」。首次派发填目标工作区、**分支名称**（完整分支名，如 `feature/order-export`，用 `git check-ref-format` 校验）、worktree 与基线分支。
4. 确认后插件依次：建/复用 worktree → 建 DSH 工作区与会话 → 把标题、来源链接、完整正文、参考资料与工作环境写进**输入框草稿**（禅道正文里的图片与附件也会下载并挂上）→ 会话标题改为 `<分支名> · <标题>` → 跳转过去。
   **不会自动发送**：你看一眼、改一改，自己按发送。

## 数据与失败模式

- 设置：`~/.dsh/zentao/settings.json`；派发记录：`~/.dsh/zentao/state.json`。
- 派发记录按 `zentao:<条目 id>`（如 `zentao:task-31`）区分需求、任务与缺陷。
- 就地派发默认开启智能保留本地改动；关闭后需要干净工作区。已有同名 worktree 但停在别的分支时报冲突，不会强改。
- 面板每分钟刷新分支与会话状态；宿主查询暂时失败时显示「状态暂不可用」，草稿准备中断可重试原会话。

## 开发

```bash
npm test     # 纯函数、禅道 v1/v2 客户端、git 流程、派发、宿主路由、客户端渲染
```

改完代码后，已安装的 bundle 需要重启 DSH 才会加载新的 JS 代次。

## 限制

- 只读不写：不改禅道里的状态、不写备注（v2 已经有 `tasks/{id}/start|finish`、`bugs/{id}/resolve` 等端点，可作为下一步）。
- 处理人过滤在本地做，范围选得多时请求量会随产品/执行数增长。
- 附件上限：单图 6MB、总附件 20MB。
- 不代替 Agent 执行计划；派发后由会话里的 Agent 自己规划与实现。
